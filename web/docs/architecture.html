KindleUnpack 架构解剖

一个把非 DRM 的 Kindle / MobiPocket 电子书逆向还原成可编辑源文件的解包器。 它不做格式转换，而是重建 Kindlegen 打包前的中间产物——所以理解它的关键， 是理解它如何把一条扁平的 PalmDB 记录序列，重新分层成"容器 → 元数据 → 索引 → 标记语言 → 打包"。

01

它做什么：四种输入，四种输出

输出形态完全由输入书的物理结构决定——这不是一个转换器，是一个按结构分派的还原器。

输入类型判定依据输出
.mobi .prc .azw Mobi6/7，version ≠ 8 旧式 book.html + Images/ + content.opf
.azw3 KF8，version = 8 或 start ≠ 0 epub 目录树 + .epub 压缩包
Combo 正文中夹一个 BOUNDARY 段 上面两套，分别落在 mobi7/ 与 mobi8/
.azw4 Print Replica，rawML 首 4 字节为 %MOP 原始 PDF + 附属二进制段 + OPF
02

五层架构

每一层只依赖下一层，且都只暴露极窄的接口——这是全库能同时支撑三种书型的原因。

编排层
kindleunpack.py
唯一的流程控制中心。unpackBook() 负责判定书型、驱动资源扫描、把每个 MobiHeader 分派到对应路径； 其余全部 process*() 函数都是"按 section magic 分派的处理器"。全局开关 DUMP / WRITE_RAW_DATA / SPLIT_COMBO_MOBIS 也定义在这一层。
容器 / 元数据层
mobi_sectionermobi_headermobi_uncompressmobi_splitmobi_utils
Sectionizer 把文件变成"第 n 段字节"；MobiHeader 把 record 0 变成元数据字典 + 一组索引段号； 解压器（PalmDOC / HUFF-CDIC）以函数指针形式挂在 MobiHeader.unpack 上；mobi_split 绕过前两者， 直接对字节做 PDB 结构编辑。
索引层
mobi_index
唯一的 INDX 解析器（TAGX 标签表 / IDXT 条目偏移 / CTOC 字符串池）。 NCX、KF8 骨架、KF8 片段、Guide、字典词条、页码表全部共用它—— 这是整库复用度最高的一块代码。
格式重建层
mobi_k8procmobi_htmlmobi_k8rescmobiml2xhtmlmobi_ncxmobi_navmobi_pagemapmobi_dict
Mobi7 与 KF8 在这里分道扬镳：前者做"字节偏移锚点回填"，后者做"骨架 / 片段重组 + kindle:* URI 改写"。 两条路都用手写扫描器而非 XML 库——因为 Kindlegen 的产物常常并不合法。
输出层
mobi_opfmobi_coverunpack_structure
三条路径最终都汇聚到 OPFProcessor.writeOPF()；fileNames 负责目录树与 OCF 规范的 epub 打包 （mimetype 必须首个写入且不压缩）。
横切
compatibility_utilsunipathimghdr
Py2/Py3 兼容层（bchr / bord / bstr 专门解决 Py3 下 bytes[i] 返回 int 的问题）、 统一 unicode 路径封装、以及标准库 imghdr 在 Python 3.13 被移除后的内置替代品。
03

主流水线 unpackBook()

编号即真实执行顺序。lib/kindleunpack.py:876

  1. 建立输出目录树
    fileNames(infile, outdir) 立刻创建 mobi7/、mobi7/Images/、HDImages/。 epub 相关目录不在此刻建——只有确认有 KF8 部分后，才调 makeK8Struct()。
  2. 装载 PalmDB 容器
    Sectionizer(infile) 把整个文件读进内存，一次性解出全部记录偏移表， 并在末尾追加一个 (filelength, 0) 哨兵——这样"第 n 段的结束"永远等于"第 n+1 段的开始"，连最后一段也不例外。
    随后校验 ident ∈ {BOOKMOBI, TEXtREAd}，否则直接抛 unpackException('Invalid file format')。
  3. 解析 record 0
    MobiHeader(sect, 0)。这一步做完，书的一切元信息都已就位：标题、语言、metadata 字典、 压缩器函数指针、以及 firstresource / ncxidx / skelidx / fragidx / guideidx / fdst 等索引段号。
  4. 判定书型
    三条岔路，见下方判定逻辑。判定结果决定要不要建 epub 目录、要不要跑拆分。
  5. 可选：拆分合体书
    mobi_split(infile) 在字节层面重建两个独立 PDB，产出 mobi7-<name>.mobi 与 mobi8-<name>.azw3。它与前面的 Sectionizer / MobiHeader 完全不共享代码，自己按常量偏移读 record 0。
  6. 逐 MobiHeader 处理
    process_all_mobi_headers()：对 mhlst 里的每个 MobiHeader （Mobi7 一个、KF8 一个）依次执行"元数据 → DRM 检查 → 资源段扫描 → 按类型出口"。
    DRM 检查很干脆：isEncrypted() 为真就 raise unpackException('Book is encrypted')，本库不处理任何加密内容。
  7. 收尾归类
    processUnknownSections() 把扫描过后仍无描述的段统一归类命名—— 识别出三连空字节 / 双空字节 / 单空字节的终止标记、INDX 段，以及真正的"神秘段"。

阶段一：资源段扫描

从 mh.firstresource 遍历到上界，按 record 起始 4 字节 magic 分派。这段循环同时是 rscnames 数组的构建过程。

rscnames 是这一阶段的真正产物。它是一个与 section 一一对应的名字数组， 下标就是正文里 recindex="N" 和 kindle:embed:<base32> 引用资源的编号。 由此推出两条硬约束：

  • 任何"不产生资源"的段都必须 append(None) 占位，绝不能跳过——否则后面所有资源编号错位。
  • 这正是 mobi_split 删除 RESC / FONT 时用 nullsection() 而非 deletesectionrange() 的原因： 前者清空段体但保留 record 槽位，编号不变；后者会整体前移，毁掉全部图片引用。

同时维护的 rsc_ptr 记录"第一个真正的资源"位置，用于让 CRES 高清图对回它所替换的原图。

05

阶段二：三条重建路径

同一份 rawML，三种完全不同的还原策略。

Mobi7 路径

字节偏移锚点回填 processMobi7() 
rawML = mh.getRawML()              # 逐正文记录剥 trailer → 解压 → 拼接
ncx_data = ncxExtract.parseNCX()
positionMap = dictSupport(...).getPositionMap()   # 仅字典书

srctext = HTMLProcessor.findAnchors(rawML, ncx_data, positionMap)
srctext, usedmap = HTMLProcessor.insertHREFS()

findAnchors() 的顺序陷阱。它先把所有 filepos=\d+ 出现的位置收集起来， 在每个字节偏移处生成一个空锚点 <a id="fileposN" />，最后统一排序拼装回原文。 必须先收集后拼装——边扫描边插入会让每个插入点之后的偏移全部失效。

insertHREFS() 做三件事：filepos=0*N → href="#fileposN"； recindex="N" → src="Images/<rscnames[N-1]>"；在 <html> 之后补 charset meta。

guide 从原文正则抓取（<guide>(.*)</guide>），修正大小写、把 filepos 换成 #fileposN，再叠加 EXTH 116 StartOffset。

mobiml2xhtml.MobiMLConverter 是同一思路的老式独立实现（MOBI 专有标签 → XHTML + 内联 CSS 提类）， 嵌套 <font> 用 font_history 栈展开成线性序列。它是一个可以脱离插件单独运行的遗留组件。

KF8 路径

骨架 / 片段重组 + URI 改写 processMobi8() 
rawML
 ├─ K8Processor.buildParts(rawML)          ← 核心
 ├─ guide ← Guide INDX（空则回退 EXTH 116）        ─┐
 ├─ PageMapProcessor → page-map.xml                 │

① buildParts() 是理解 KF8 的钥匙。Kindlegen 把正文拆成若干 <html> 骨架（skeleton），每个骨架里按插入点塞入若干 片段（fragment）；两者都存在 INDX 索引里。重组算法就是：

  1. FDST 切 flows —— FDST 段给出若干偏移，相邻两两切片， 把 rawML 尾部那些非正文内容（CSS / SVG）切出来。代码只取每对的起点，末尾用 mh.rawSize 收尾。
  2. 骨架 + 片段重组 —— 取出骨架字节块，按片段表的插入点切 head / tail， 拼 head + fragment + tail，插入点随每次插入推进。每个骨架产出一个 Text/partNNNN.xhtml。
  3. flows 分类 —— 含 <svg> 且内含 <image> 的标记为 inline （稍后原地内联进正文，因为浏览器不渲染"SVG 里再引用栅格图"）；其余 CSS 落 Styles/、SVG 落 Images/。

若插入点落在标签中间，locate_beg_end_of_tag() 会找到该 aid 标签的真实边界重算插入点并回写 fragtbl—— 这是对 Kindlegen 产物瑕疵的容错。

② buildXHTML() 是纯正则改写，且顺序敏感。 kindle:pos 必须最先处理，因为后续改写会破坏位置信息：

遇到处理
kindle:pos:fid:<b32>:off:<b32>getIDTagByPosFid() → filename 或 filename#idtag
aid="…"一律删除；仅 linked_aids 里的保留成 id="aid-NNN"
data-AmznPageBreak→ style="page-break-after:…"
kindle:embed:<b32>base32 解出 1-based 索引 → rscnames[n-1] → ../Images/ 或 ../Fonts/
kindle:flow:<b32>?mime=…inline 则整段替换，否则 → ../Styles/ 或 ../Images/
<svg viewbox> <li value>修正为合法 XHTML（viewBox；删除非法 value）
fixed-layout注入 <meta name="viewport">

③ K8RESCProcessor 补回 Kindlegen 丢掉的信息。 RESC 段里存着原始 content.opf 的片段——从中恢复 spine 顺序（skelid → itemref）、 page-progression-direction，以及 EPUB3 的 refines 元数据。 它用手写容错扫描器（parseresc / parsetag / resc_tag_iter）而非 XML 库， 因为 Kindlegen 写出的 OPF 片段并不严格合法。

Print Replica 路径

表驱动切片 processPrintReplica()

rawML 本身就是一张表：先读 numTables，再逐表读 section 数， 然后按 (offset, length) 对切出每一段。约定每张表的第 0 段是 PDF，其余是二进制数据。

产出 <base>.001.pdf（第 1 表）与 <base>.NNN.MMM.data，最后仍生成一个 OPF 去描述它们。

整个切片过程包在 try/except 里——表结构损坏时只打印错误，不中断整本书的解包。

06

贯穿全库的六个核心概念

这六件事理解了，剩下的模块基本只是排列组合。

Section ≡ PalmDB record

Sectionizer 只干一件事：loadSection(n)。所有 MOBI 语义都在 MobiHeader 里。

record 0 的物理结构是 16B PalmDOC 前缀 + MOBI header + EXTH + 标题， 所有内部偏移都相对 record 0，由 MobiHeader.__init__ 逐个 += self.start 转成绝对段号。

self.start 对 KF8 部分就是 EXTH 121 指出的段号，这也正是 isK8() 的判据。

三种压缩

1 无压缩 · 2 PalmDOC LZ77 变体 · 0x4448（'DH'）HUFF/CDIC。

HUFF/CDIC 是静态 Huffman + 短语字典：dict1 按码字首字节索引，dict2 给出每个码长的 min/max， 构成 canonical 解码表。CDIC 短语最高位 0x8000 表示"是否已展开"，未展开则惰性递归解压并 memoize。

CDIC 可以有多段，增量拼接进同一个短语表。

Trailer 剥离

正文记录末尾附加的元数据，长度用变长 base-128 从末尾反向扫描得到（高位 0x80 为终止标志），逐条剥离。

仅在 BOOKMOBI + mobi_length ≥ 0xE4 + version ≥ 5 时启用；PalmDOC 没有 trailer。

两套位置引用体系

这是 Mobi7 与 KF8 最本质的区别：

Mobi7KF8
跳转filepos=Nkindle:pos:fid:…
资源recindex="N"kindle:embed:…
样式内联属性kindle:flow:…

INDX / TAGX / CTOC

所有索引的统一底层：INDX 头 13 个 32 位字段 → TAGX 标签表 (tag, valuesPerEntry, mask, endFlag) → IDXT 条目偏移 → 每条目是 文本长度 + key 文本 + 控制字节 + VWI 变长值。

CTOC 是配套的字符串池——NCX 标题、字典词条都存这里。多段 CTOC 时用 rec_off += 0x10000 做偏移基址防冲突。

usedmap 三态

'used' / 'not used' / 'maybe'。OPF manifest 跳过 not used， makeEPUB() 只拷贝 used 的资源。

封面缩略图被故意标成 not used——因为 Kindlegen 会重新生成它，放进 manifest 反而是错的。

输出目录结构

mobi8/ 下的布局严格遵循 EPUB OCF 规范。

<outdir>/
├── mobi7/
│   ├── book.html          content.opf        toc.ncx
│   └── Images/            imageNNNNN.jpg · cover*.jpg · font*.ttf
├── mobi8/                                    ← 仅 KF8 / Combo
│   ├── META-INF/  container.xml  [encryption.xml]
│   ├── OEBPS/
│   │   ├── content.opf  toc.ncx  nav.xhtml  page-map.xml
│   │   ├── Text/    part0000.xhtml … cover_page.xhtml
│   │   ├── Styles/  style0001.css …
│   │   ├── Images/  含 svgimgNNNN.svg
│   │   └── Fonts/
│   └── <name>.epub                          ← 打包结果
├── HDImages/                                ← CRES 资源
├── header.dat  header_K8.dat                ← -d dump
├── kindlegensrc.zip  kindlegenbuild.log     ← 若原书内嵌
└── mobi7-<name>.mobi  mobi8-<name>.azw3      ← -s 拆分产物

makeEPUB() 有两个容易被误读的细节。其一，mimetype 必须 第一个写入且不压缩（ZIP_STORED）——标准库 zipfile 不允许给 ZipInfo 传 compress_type，所以自定义了一个子类。其二，有混淆字体时会额外写 META-INF/encryption.xml（Adobe enc#RC 算法），并用 OPF 的 uid 派生 XOR key 重新混淆字体文件。

09

已知缺陷与设计取向

阅读源码时最容易踩空的地方。

设计取向
  • 全库不用 XML 库解析输入。mobiml2xhtml、mobi_k8resc 都是手写字节 / 字符扫描器。 原因是 Kindlegen 产出的标记常不合法，DOM 解析会直接抛异常。
  • 无图像重采样。代码里没有任何 resize 调用。封面的"缩放"靠 SVG viewBox + preserveAspectRatio 交给阅读器完成；高清替换是 CRES 段的整文件覆盖。
  • 不处理 DRM。isEncrypted() 为真即抛异常，没有降级路径。
  • 有意保留 EPUB2 兼容产物。OPFProcessor 顶部的 EPUB3_WITH_NCX 与 EPUB3_WITH_GUIDE 即使在产出 EPUB3 时也置为 True，源码注释明确写着"不要改成 False"。
具体缺陷
  • mobi_k8resc.py:119 的拼写错误。page-progession-direction 少了一个 r， 导致该属性永远读不到值，这条路径上的 RTL 检测完全失效。修正拼写即可，但会改变现有行为。
  • mobi_k8proc.py:190 的硬编码切片。aidtext = idtext[12:-2] 依赖 aid 文本的确切格式，一旦格式变化就会取错。好在只影响容错分支 locate_beg_end_of_tag。
  • mobi_k8resc.py:55 用 data.find(b'\x00') 找 RESC 结尾。 若 RESC 正文里含 NUL 字节会被提前截断——只触发 Warning，不报错，所以问题会静默传播。
  • mobi_header.py 偏移表里的重复 key。'unknown0' 出现两次、 'Unknown ' 出现 13 次，dict 字面量后者覆盖前者，导致 dumpheader 输出缺项。不影响解析逻辑，只影响 dump。
  • mobi_k8proc.py:83 的 FDST 表只保留每对的起点。 这意味着相邻 flow 段必须首尾连续，否则中间字节会被丢弃。
  • mobi_header.py:653 在 fdstcnt ≤ 1 时主动丢弃 FDST。 因为此时段号很可能是垃圾值——这是一个刻意的防御，而非 bug。
